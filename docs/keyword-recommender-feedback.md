# "오늘의 키워드" 추천기 — 로직 개선 피드백

사용자 분석기가 매일 내주는 **"오늘의 키워드"** 추천 목록에 대한 실측 기록 + 로직 수정 제안.

- **역할 분담 전제**: 추천기는 *시드 후보를 넓게 훑는 도구*, 발행 결정은 `/api/judge`. 추천기가 판정까지 하라는 요구가 아니다
- 이 문서의 목적: 걸러내는 비용이 매 세션 Claude 쪽에 반복해서 발생하고 있으므로, **어느 필터를 도구 쪽으로 옮기면 비용이 사라지는지** 근거와 함께 남긴다
- 관련: `../CLAUDE.md` "시드 공급 워크플로" / "발행 하한" · [research-backlog.md](./research-backlog.md) 판정 완료 큐

#### 이 회차가 새로 드러낸 것 3가지

**① ✅ 플래그가 우리 하한도 ledger도 모른다는 직접 증거가 나왔다.**
`꾸뛰르 염색샴푸`·`르베로 염색샴푸`가 **✅를 달고 재등장**했다. 꾸뛰르는 기존 `dyeing-shampoo-brand-comparison` 이 이미 커버하는 자기잠식이고, 르베로는 07-31에 하한 미달로 거절한 건이다. 지금까지 "무플래그 후보는 판정 안 된 것"으로만 정리해왔는데, **✅ 플래그도 우리 기준으로는 재검증 대상**이라는 뜻이다 → 6순위(ledger 대조)·1순위(⛔ 목록 입력)의 근거가 강화된다.

**② ✅ 플래그 적중률이 처음으로 측정됐다 — 3개 중 2개.**
`세포랩 블랙라벨`은 점수 **99.4**(이 회차 1위)에 경쟁률 0.06으로 지표가 완벽했는데, 1면 상위 4슬롯이 전부 홈쇼핑·커머스였다. 특히 홈쇼핑 편성표 사이트(hsmoa 계열)가 **4개 도메인으로 도배**된 것이 결정적이었다 — 검색 의도가 "방송 언제 하나"라는 자백이다. **문서 289건이 얇은 이유가 정보 진공이 아니라 "블로그가 안 쌓이는 자리"** 였고, 이는 3순위(쇼핑 SERP 감점)가 여전히 미해결임을 보여준다.

**③ 재등장률이 처음으로 정량화됐다 — 30개 중 4개(13%).**
하루치로 받으면 "어제 본 것 같은데" 수준이었으나 3일치를 겹쳐 보니 비율이 나온다. 1순위(⛔ 목록 입력) 요청의 비용 근거로 쓸 수 있다.

#### 큐가 완충 장치로 작동한 첫 확인

`제이숲 염색샴푸`는 **07-31 회차에서 "하한 통과하나 judge 미실행"으로 큐에 넣어둔 건**이다(당시 기대클릭 352). 이번에 judge ✅를 받고 발행됐다. 후보가 안 나오는 날을 큐가 메운다는 설계가 실제로 돌아간 사례이므로, **추천기 적중률이 낮은 회차의 손실이 그대로 손실이 아니다**는 점도 함께 기록해둔다.

## 구조적 원인 3가지

### ① 판정 이력을 모른다 — 매일 같은 후보가 돌아온다

`자두 효능`(07-28 ⛔ → 07-29 재등장), `과탄산소다 사용법`(07-29 ⛔ → 07-30 재등장). 점수가 높으니 매일 상위에 뜬다. **⛔ 판정은 SERP가 바뀌지 않는 한 유효한데, 그 사실이 도구에 남지 않는다.**

현재는 Claude 쪽에서 `research-backlog.md` ⛔ 표와 수동 대조해 막고 있다. 이 문서가 없으면 판정 비용을 매일 다시 지불한다.

### ② 기회지수가 SERP 성격을 못 본다 — 경쟁률 0.05의 두 얼굴

경쟁률(문서수÷검색량)이 낮은 데는 두 가지 원인이 있는데 점수는 이를 구분하지 못한다.

| 원인 | 예 | 실제 가치 |
|---|---|---|
| **정보 진공** — 아무도 이 답을 안 썼다 | 메디올 새치염색약 (문서 302) | 높음. 1위 기대 |
| **쇼핑 SERP** — 블로그가 쌓일 자리가 아니다 | 포카리스웨트 340 무라벨 (문서 24) | 낮음. 1·2위가 쿠팡·11번가 |

2026-07-30 `포카리스웨트 340 무라벨` 은 **문서 24건 · 기회지수 89 · 경쟁률 0.02** 로 지표상 최상급이었고 judge 도 ✅(사유: "강자 소수 혼재하나 지배적 아님")를 줬다. 그런데 SERP 실제 배열은:

```
rank1 coupang · rank2 11st · rank4 smartstore · rank13 ssg · rank16 enuri
blog.naver.com 은 rank3 하나뿐
```

문서가 24건인 이유가 "정보 진공"이 아니라 **쇼핑 검색이라 블로그 문서 자체가 안 쌓이는 자리**였다. 3위를 잡아도 위에서 클릭이 다 빠진다.

### ③ 볼륨을 실익으로 환산하지 않는다

점수는 "뚫리는가"에 가깝고 "뚫려서 얼마나 오는가"가 빠져 있다. 같은 볼륨이라도 문서수에 따라 기대 순위가 달라 실익이 3배 이상 갈린다. 판정 기준은 `../CLAUDE.md` "발행 하한 — 기대 월클릭" 참조.

## 🎯 요청은 하나다 — **죽은 칸 제거** (2026-07-31 정리)

> 📌 **전달 보류 중 (2026-07-31 결정).** 2026-07-31 회차에서 기대클릭 1,333 짜리를 건졌으므로 현행 도구로 몇 회차 더 받아본다. 죽은 칸 비율이 계속 4/10 수준으로 유지되면 그때 아래 요청을 넘긴다. **매 회차 "실측 적중률"에 죽은 칸 개수를 기록할 것** — 이게 전달 여부의 판단 근거다.


⚠️ **아래 제안 목록을 통째로 넘기지 말 것.** 대부분은 우리가 자력으로 30초 안에 처리할 수 있고, 그런 걸 요청하면 진짜 필요한 항목이 묻힌다.

| 제안 | 우리가 자력으로 되나 | 처리 |
|---|---|---|
| 기대클릭 계산·정렬 | **된다** — `검색량 × 경쟁률 = 문서수` 라 추천 목록만으로 산출됨 | 우리 쪽에서 함 |
| 문서 20,000 초과 judge 강제 | **된다** — 우리가 judge 를 부르면 됨 | 우리 쪽에서 함 |
| ledger 자기잠식 대조 | **된다** — 5초 조회 | 우리 쪽에서 함 |
| **10칸 중 죽은 칸 제거** | **안 된다** — 목록 밖 후보는 관측 불가 | **이것만 요청** |

**죽은 칸** = judge 를 부르기도 전에 탈락이 확정된 후보. 2026-07-31 기준 10칸 중 **4칸**이 여기 해당했다.

| 죽은 유형 | 해당 | 도구가 걸 수 있는 필터 |
|---|---|---|
| 기대클릭 300 미만 | `압스`(197) · `르베로`(192) | `검색량 × CTR계수(문서수 구간)` 하한 |
| 발행글이 이미 커버 | `꾸뛰르 염색샴푸` | 제외 목록 입력 |
| ⛔ 판정 이력 | `지디 지압슬리퍼` | 제외 목록 입력 |

```
CTR계수: 문서 <100 → 0.30 | 100~10,000 → 0.15 | >10,000 → 0.06
(표본이 구간당 1~3개뿐 — 하드코딩 말고 설정값으로. 근거: ../CLAUDE.md "전환율 — 우리 실측치")
```

**왜 이것만 중요한가**: 정렬은 우리가 다시 하면 되지만, **밀려서 목록에 안 뜬 후보는 존재 자체를 모른다.** 2026-07-31 `지압슬리퍼` 시드는 브랜드 파생을 6개나 냈고 그중 4개가 하한을 넘긴 좋은 시드였는데, 죽은 칸 4개가 그 시드의 나머지 꼬리를 밀어냈을 가능성이 크다. **10칸을 전부 살아있는 후보로 채우는 것**이 도구 쪽에서만 가능한 유일한 개선이다.

## 로직 수정 제안 전문 (근거 보존용 — 요청 시엔 위 한 항목만 넘긴다)

### 0순위 — 정렬 기준을 점수에서 **기대클릭**으로 바꿀 것 (2026-07-31 승격)

기존 4순위("기대클릭 컬럼 추가")를 최상위로 올린다. 컬럼을 옆에 하나 더 붙이는 게 아니라 **정렬 키를 교체**하는 요구다.

```
기대클릭 = 월검색량 × CTR계수(문서수 구간)
CTR계수:  문서 < 100 → 0.30 | 100~10,000 → 0.15 | > 10,000 → 0.06
```

- 계수 근거는 `../CLAUDE.md` "전환율 — 우리 실측치". 표본이 구간당 1~3개뿐이라 계수는 스냅샷마다 갱신된다 — **도구에 하드코딩하지 말고 설정값으로 뺄 것**
- **기대클릭 300 미만은 목록에서 제외**한다. 2026-07-31 기준 10개 중 2개(`압스`·`르베로`)가 여기서 사라지고, 그 자리에 다른 시드 후보가 올라온다
- 이 하나로 "점수 6위가 실제 최대어"인 역상관이 해소된다

### 1순위 — ⛔ 제외 목록 입력받기 (효과 최대, 구현 최소)

추천 생성 시 **제외 키워드 목록을 입력으로 받아 필터**한다. `research-backlog.md` ⛔ 표를 그대로 넘기면 된다.

- 이것만으로 07-29·07-30 의 재등장 2건이 사라진다
- 도구가 판정 이력을 저장할 필요 없이 **호출 시 목록만 받으면** 된다

### 2순위 — ⛔ 플래그가 붙은 후보는 목록에서 빼기

`포카리스웨트 분말`·`효능` 은 ⛔ 를 **달고** 추천 목록에 올라왔다. 판정이 이미 났는데 점수가 높다고 노출하면 목록의 신뢰도가 떨어진다. 최소한 상위 정렬에서는 제외.

### 3순위 — 쇼핑 SERP 감점

1면 rank 1~2 에 커머스 도메인(`coupang.com`·`11st.co.kr`·`smartstore.naver.com`·`ssg.com`·`enuri.com`·`lotteon.com`)이 있으면 기회지수를 감점한다. judge `buckets` 의 `platform` 분류를 그대로 쓸 수 있다.

- 이 필터 하나가 2026-07-30 후보 10개 중 **5개**를 걸러낸다

### 4순위 — 기대클릭 컬럼 추가 → **0순위로 승격됨** (2026-07-31)

문서 상단 0순위 항목 참조. 2026-07-31 회차에서 점수 6위가 실제 최대어(기대클릭 1,333)로 드러나 정렬 기준 교체 요구로 격상했다.

### 5순위 — 문서수 20,000 초과 후보는 judge 강제

`지압슬리퍼`(58,318)·`이동식에어컨`(191,358) 이 점수 72.9·80.4 로 그냥 목록에 올라왔고, judge 를 돌리자 **둘 다 ⛔** 였다(쿠팡 33% / kca.go.kr rank3). head 는 기대클릭이 커서 0순위 필터를 통과하므로 별도 게이트가 필요하다.

- ⚠️ **문서수로 자동 거절하라는 게 아니다.** `로레알 염색약`(문서 26,395)은 인컴번트가 없어 ✅ 였다. 거절 근거는 문서수가 아니라 인컴번트 유무이므로, 문서수는 **judge 를 부르는 트리거**로만 쓴다

### 6순위 — 발행글 목록(ledger) 대조로 자기잠식 차단

`꾸뛰르 염색샴푸`(점수 2위·90.8)는 지표가 전부 통과였는데 기존 발행글 `dyeing-shampoo-brand-comparison`(조혜련 염색샴푸=꾸띄르 4종 비교)이 이미 커버 중이라 탈락했다. 07-28 `플럼바고 외목대` 와 같은 유형의 두 번째 사례다.

- ⛔ 제외 목록(1순위)과 **같은 인터페이스로 처리 가능**하다 — 발행 완료 키워드 목록을 제외 입력에 함께 넘기면 된다. 별도 구현이 필요 없다

### 참고 — 노출광고수는 유지할 것

`CTR`·`노출광고수` 는 keyword-radar API 에 없는 데이터라 추천기의 고유 가치다. 특히 **노출광고수 1~3 = 광고주 미입찰 = 순수 정보 검색**이라는 신호는 다른 데서 못 얻는다.

⚠️ 단 `CTR` 은 **광고 클릭률**이지 오가닉이 아니다. 2026-07-30 Claude 가 이를 오가닉으로 오독해 `딤채 김치냉장고 고장` 축을 잘못 배제한 사례가 있다. 컬럼명을 `광고CTR` 로 바꾸면 오독이 사라진다.

## 판단 — 추천기를 계속 쓸 것인가

**쓴다.** 적중률 1/10 은 낮지만 추천기의 역할은 시드 발굴이지 판정이 아니다. 2026-07-30 에도 `김치냉장고` 시드는 여기서 나왔고, 그 시드에서 기대클릭 274짜리 후보가 하나 나왔다.

다만 **목록을 받자마자 ⛔ 표와 대조하는 것을 첫 단계로 고정**한다. 1순위 제안이 반영되면 이 단계는 없앤다.
